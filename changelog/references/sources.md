# Primary guidance and examples

These sources inform the workflow, not a mandatory template. Read the relevant guidance when establishing an approach, and refresh external facts when their currency matters. Keep that research bounded: the work is to produce the update.

| Source | Application in this skill |
| --- | --- |
| [Servo's monthly-update workflow](https://github.com/servo/servo.org#how-to-write-a-monthly-update) | Inventory the period before writing, triage changes, and use implementation context to turn a large history into understandable updates. |
| [Keep a Changelog](https://keepachangelog.com/en/2.0.0/) | Select notable changes for people. A raw commit list is not an adequate changelog. Its versioned category format is optional here because this skill also produces cross-repository engineering reports. |
| [Google developer documentation highlights](https://developers.google.com/style/highlights) | Address the reader directly, use clear subjects and verbs, and explain unfamiliar concepts without inflating the prose. |
| [January in Servo](https://servo.org/blog/2026/02/28/january-in-servo/) | A real engineering update shows how to explain concrete behavior changes and distinguish existing features from fixes and unfinished work. |
| [October 2025 in Ladybird](https://buttondown.com/ladybird/archive/this-month-in-ladybird-october-2025/) | Connect implementation work to what it enables while keeping partial feature support and measurement scope visible. |
| [Wikipedia: Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing) | Use as an editorial checklist for inflated significance, repetition, mechanical structure, and unsupported claims. It is not an AI detector. |
| [OpenAI skill guidance](https://developers.openai.com/codex/skills) | Keep the entrypoint focused; put detailed procedures and deterministic tools in supporting files; test both activation and output quality. |

No model ranking establishes that a model can write a useful technical changelog. If comparing tools or models, use the same verified changes, assess factual fidelity and reader comprehension, and keep the comparison small. Consult the vendor's current documentation for availability, capabilities, and data handling rather than freezing product claims into this skill.
